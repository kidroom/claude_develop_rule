# 物件導向與設計原則（SOLID）

何時該設計、何時該抽象見 `simple-design.md`；本檔規範決定要設計時怎麼做。

## SOLID
| 原則 | 說明 | 執行規範 | 過度套用的徵兆 |
|---|---|---|---|
| 單一職責 SRP | 一個模組只有一個改變的理由 | 需要用「和」才能描述職責時拆分；依變化原因拆，不依行數拆 | 拆成大量只有一個方法、彼此緊密呼叫的類別 |
| 開放封閉 OCP | 對擴充開放、對修改封閉 | 擴充點建立後，新增同類變化只新增程式碼，不改既有分支；建立時機依 `simple-design.md` | 為想像中的變化預留掛鉤 |
| 里氏替換 LSP | 子型別必須能完全替換父型別 | 子類別不得要求更嚴格的輸入、提供更弱的保證、丟出父型別沒有的例外或留空實作；做不到就改用組合 | — |
| 介面隔離 ISP | 使用方不依賴用不到的方法 | 介面由使用方定義、依角色命名並可讀寫分離（`OrderReader`／`OrderWriter`）；實作中出現「不支援」例外代表介面太大 | 每個方法一個介面 |
| 依賴反轉 DIP | 高層模組依賴抽象，不依賴細節 | 依賴由建構子或參數注入，不在內部 `new` 外部資源；分層方向見 `architecture.md` | 連純函式、值物件都抽介面 |

## 其他設計原則
| 原則 | 執行規範 |
|---|---|
| 高內聚低耦合 | 一起變動的程式碼放在一起；模組之間只透過公開介面溝通 |
| 關注點分離 | 業務規則、I/O、呈現放在不同的函式或模組 |
| 組合優於繼承 | 預設用組合；繼承只用於真正的 is-a，深度 ≤ 2 層；不以繼承共用程式碼 |
| 封裝 | 狀態只經表達意圖的方法變更（`order.cancel()`），不提供公開 setter；公開集合以唯讀型別暴露，不回傳內部可變集合 |
| 最小可見性 | 類別與成員預設最小可見範圍、預設不可繼承；需要擴充時才放寬 |
| Tell, Don't Ask | 邏輯放在擁有資料的物件上，不在外部讀狀態再判斷 |
| 迪米特法則 | 只與直接協作者互動，避免 `a.getB().getC().do()` |
| 不可變優先 | 值物件（金額、Email、日期區間）與資料載體（DTO、命令、事件）不可變，修改時回傳新物件 |
| 有效建構 | 不變條件在建構子或工廠方法中強制，物件不得處於非法狀態 |
| 慣例優於設定 | 命名、目錄、註冊方式保持一致，讓人與 AI 能依慣例推斷位置 |

## 介面與分支
「只有一個實作的介面」是過度設計警訊。建立介面須符合任一條件，否則直接用具體類別或函式：
1. 已經有兩個以上的實作。
2. 需要在測試中替換外部依賴，且無法用傳入函式等更簡單的方式。
3. 變化方向已確定會持續增加（見 `simple-design.md` 平衡原則）。

對封閉型別（列舉、密封階層）的分支依賴編譯器的窮舉檢查，不以 default 吞掉新增的值。

## 類別
- 需要把資料與規則綁在一起、或保護不變條件時才用類別；不建只有靜態方法的類別。
- 類別超過約 200 行或公開成員超過約 10 個時檢視拆分。

## 設計模式
模式解決特定的變動點，不是預設結構；對應情境出現才引入，並在 PR 說明理由。

| 情境 | 模式 |
|---|---|
| 同一操作依類型有不同演算法，且類型持續增加 | Strategy（以對應表分派） |
| 為既有實作加橫切行為（快取、重試、日誌） | Decorator |
| 多步驟且步驟可插拔 | Pipeline／Chain of Responsibility |
| 建構規則複雜或參數多 | Builder／Factory Method，保持不變條件 |
| 外部系統介面不合內部模型 | Adapter |
| 隔離複雜子系統 | Facade |
| 狀態機（訂單、審核流程） | State，轉移規則封裝在狀態內，不用巢狀 if 判斷狀態 |
| 資料寫入與訊息發布需一致 | Outbox |
| 未指定值的安全預設 | Null Object，取代散落的 null 檢查 |

禁止或限制：手寫 Singleton（生命週期交給 DI）、Service Locator、Repository 對外暴露可任意組合的查詢物件、Active Record（實體自帶持久化）、以繼承式 Template Method 取代組合；避免 Abstract Factory、Visitor、多層 Decorator、只有一個訂閱者的 Observer。
