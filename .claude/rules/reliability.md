# 可靠性：錯誤處理、副作用、非同步與可觀測性

## 錯誤處理
預期失敗以結果型別回傳，非預期錯誤才拋例外；例外只在系統邊界捕捉一次。

| 類型 | 例 | 處理 |
|---|---|---|
| 業務規則失敗（預期） | 庫存不足、狀態不允許 | 回傳結果型別與穩定錯誤碼 |
| 資源不存在 | 訂單不存在 | 回傳「找不到」結果 |
| 輸入格式錯誤 | 欄位缺漏 | 在邊界驗證並回報欄位明細 |
| 基礎設施錯誤（非預期） | 資料庫斷線、下游 5xx | 在該層轉成有意義的錯誤後往上拋，由全域處理器處理 |
| 程式錯誤 | 空參考、型別轉換失敗 | 視為 bug，不捕捉，進入監控 |

- 全域處理器輸出統一錯誤格式並含追蹤 ID；不暴露內部資訊（見 `security.md`）。
- 錯誤碼格式統一（如 `domain.reason`）並集中定義；一經公開即為契約，只增不改。
- 不吞例外：catch 後必須處理、轉換後重拋或記錄後重拋，禁止只記錄不回報；只捕捉能處理的例外類型。
- 不用例外控制流程；重拋保留原始堆疊，包裝時帶入原例外。
- SHOULD：自訂例外只在呼叫端需要區別處理時定義，並攜帶結構化屬性。
- 錯誤訊息包含除錯所需上下文（操作、資料識別碼）；快速失敗：前置條件不符立即失敗；能不回傳 null 就不回傳。

## 副作用
- 副作用（I/O、狀態變更、時間、亂數）只出現在明確的邊界；業務邏輯是純邏輯。
- SHOULD：處理流程固定為「讀取 → 純計算 → 寫入」，讓計算段可獨立單元測試。
- 時間、ID、亂數透過注入取得（可注入的時鐘、ID 產生器）；時間內部以 UTC 處理。
- 禁可變的全域或靜態狀態與靜態快取；跨請求狀態交由 DI 管理的長生命週期物件（見 `architecture.md`）。
- 不以隱含的執行緒或請求上下文傳遞業務資料；只允許追蹤資訊（如 TraceId），並集中由單一存取點提供。
- 不修改傳入參數後再回傳；需要變更就回傳新物件。

## 非同步、資源與並行
- I/O 路徑非同步到底；禁同步等待非同步結果；禁 fire-and-forget，背景工作用有界佇列並處理取消與例外。
- 非同步操作接受並向下傳遞取消訊號；並行要限制並發度，禁在迴圈內無上限啟動任務。
- 需釋放的資源一律用語言的自動釋放機制（using、with、defer、try-with-resources）；由容器管理的物件不手動釋放。
- HTTP client、資料庫連線等昂貴資源重用（連線池、client factory），不每次建立。
- 共享可變狀態要有同步機制，優先不可變資料與並行安全集合；非同步程式碼不用會阻塞執行緒的鎖。
- 跨程序或跨實例的互斥（排程去重、防重複扣款）用分散式鎖或資料庫唯一約束，不依賴程序內的鎖。
- 大量資料以串流處理；即使不做最佳化，也避免迴圈內查詢（N+1）與無上限載入。

## 韌性
- 每個外部呼叫都有逾時；重試只用於冪等操作，採指數退避加 jitter、≤ 3 次；禁無限重試。
- 依賴不穩定的下游時加 Circuit Breaker；SHOULD 以 Bulkhead 限制下游並發。
- 每個外部依賴有明確的失敗策略（降級、快速失敗、排隊延後），寫在該 client 的註解中。
- 產生副作用的建立操作支援冪等鍵；訊息消費者以訊息 ID 去重；「寫資料庫＋發訊息」用 Outbox。
- 長時間運行的服務支援優雅關閉：停止時完成或安全歸還進行中的工作。

## 可觀測性
目標：出錯時降級而非中斷，且能從日誌與指標快速定位原因。
- 結構化日誌（訊息範本＋具名參數，不用字串內插）並帶關聯識別碼；跨服務傳遞追蹤上下文（W3C traceparent）。
- 日誌等級：error 需要人處理、warn 自動復原但需關注、info 重要業務事件、debug 僅本機；敏感資料不進日誌（見 `security.md`）。
- SHOULD（服務型專案）：提供 RED 指標（Rate、Errors、Duration p50／p95／p99）；健康檢查分為存活與就緒，非關鍵依賴標為降級；使用廠商中立的遙測標準（如 OpenTelemetry）。
