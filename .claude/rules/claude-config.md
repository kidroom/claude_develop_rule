# Claude 設定與文件維護

`CLAUDE.md` 與沒有 `paths` 的規則每次對話都會載入。內容越長，每條規則被遵守的機率越低，所以必須保持精簡。

## 內容放哪裡
| 內容 | 位置 |
|---|---|
| 指令、技術棧、索引、已知落差 | `.claude/CLAUDE.md` |
| 每次工作都適用的原則 | `.claude/rules/*.md`（無 `paths`） |
| 只對特定檔案適用的規則 | `.claude/rules/*.md`（加 `paths`） |
| 多步驟流程 | `.claude/skills/<名稱>/SKILL.md`，細節放同目錄的附屬檔 |
| 獨立任務（如審查） | `.claude/agents/<名稱>.md` |
| 必須強制的事項 | `.claude/settings.json` 的 `permissions`、`hooks` |
| 刻意偏離規範的決定 | `docs/adr/`（`/adr`） |
| 個人偏好 | `CLAUDE.local.md`、`.claude/settings.local.json`（不進版控） |

能用工具強制的不寫成文字規則；只在特定情境需要的不放進常駐檔案。規範唯一來源為 `.claude/rules/`，不另存副本。

## 寫法
- 一條規則一行、命令句、可檢查（「函式超過 40 行必須拆」優於「函式要短」）；先寫規則再寫例外；保留 MUST／SHOULD／MAY 標記。
- 以文字與表格為主；程式碼區塊只用於格式範本與結構圖。
- 技術名詞以原文寫出，不展開解釋；範例用一句話說明情境、行為與結果。
- skill 的 description 寫「做什麼」與「使用者會怎麼說」；步驟編號，前置條件與回報分節。

## 長度上限
- `CLAUDE.md` ≤ 80 行（目標 60 行內）；常駐規則每份 ≤ 50 行；有 `paths` 的規則與 skill 每份 ≤ 80 行。
- 超過上限時先整理才能新增。

## 新增與修改
- 同一個錯誤發生第二次才寫入；先確認既有規則或 skill 是否已涵蓋，已涵蓋就改善該檔，不重複寫。
- 新規則寫入對應檔案的對應區段；新增規則檔或 skill 時同步更新 `CLAUDE.md` 的索引。
- 文件與程式不一致時，先確認哪一方正確再修改。

## Claude 的責任
- 使用者給出持續性偏好或糾正時，提議寫入哪個檔案、哪一行，經同意才寫。
- 發現檔案超過上限、內容過時或彼此矛盾時，主動提醒並建議執行 `/tidy-claude-config`。
