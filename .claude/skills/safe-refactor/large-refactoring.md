# 大型重構策略

預計超過一個 PR，或修改被多處使用的程式碼時使用。開始前先提出選用的策略、各階段與停損點，經使用者確認。

| 策略 | 適用情境 | 執行規範 |
|---|---|---|
| 平行修改 | 修改被多處使用的函式或介面 | 新增新介面並標記舊介面 @deprecated → 分批遷移呼叫端 → 確認無引用後移除舊介面，每階段獨立 PR |
| 抽象分支 | 替換被廣泛使用的實作 | 先加抽象層讓呼叫端透過它使用 → 實作新版並以開關切換 → 穩定後移除舊實作與開關 |
| 絞殺者模式 | 逐步取代大型舊系統或模組 | 新系統從邊緣功能開始逐一接手，每次只遷移一個功能單元 |
| 米卡多方法 | 修改之間有糾纏的前置依賴 | 嘗試修改失敗時，記錄阻礙的前置修改並退回所有變更；從最底層可完成的修改開始逐一往上 |

## 共同要求
- 每個階段結束時系統都可運作、可合併。
- 抽象分支與絞殺者模式引入的開關與暫時抽象層，是策略的一部分，完成後必須移除，不留下成為過度設計。
- 米卡多方法退回的只是本次嘗試的未提交變更；已記錄的依賴圖要保留在回報中。
