# 修 bug

## 步驟
1. **重現**：寫下輸入、預期、實際結果；定位到層與函式。根因不確定時先診斷，不猜著改。
2. **影響**：觸及影響分析項目先執行 `/impact-analysis`；修改既有行為依 `change-and-release.md`。
3. **先寫測試**：撰寫能重現 bug 的測試，執行並確認因為該 bug 而失敗，回報後等待確認。周邊沒有測試的既有行為先補特性測試。
4. **最小修正**：只改根因；有副作用要明說。
5. **驗證**：該測試轉綠；完整測試、型別檢查、lint 全部通過。
6. **提交**：核對 `/xp-cycle` 的 checklist.md 後 commit（`fix: ...`）。

## 回報
根因、修改的檔案、新增的測試名稱、影響範圍、是否需要 feature flag、回退方案。

## 禁止
- 以空 catch、把 null 換成預設值、加上重試等方式掩蓋問題。
- 因為沒有測試環境就略過測試；先建立，或明確告知無法執行。
