# XP 標準工作循環

規則依 `.claude/rules/workflow.md`；本 skill 提供各步驟的做法與格式。

## 1. 計畫
- 任務超過一個小 PR 時，先提出垂直切片的拆分方案（每片可運作、可合併），確認後只做第一片。
- 提出計畫，使用者確認前不修改任何檔案：
```
任務：一句話說明
驗收條件（以使用者行為描述，每條對應至少一個測試）：
- …
步驟：
1. …
影響檔案：
- path（新增／修改）
設計取捨（若有）：
- 選項 A：… 利／弊
- 選項 B：… 利／弊
```

## 2. 紅燈
1. 從驗收條件挑下一個最小的行為，以使用者行為撰寫測試。
2. 執行測試，確認因為**預期的原因**失敗，而不是語法或匯入錯誤。
3. 回報測試內容與失敗輸出，等使用者確認；同一個驗收條件的多個測試可一次提出。

## 3～6. 綠燈、重構、驗證、提交
- **綠燈**：撰寫剛好能通過測試的最少程式碼，可以先寫得很直接；執行測試確認全綠。
- **重構**：每次調整後重跑測試；較大的結構調整用 `/safe-refactor`。
- **提交**：逐項核對 [checklist.md](checklist.md)，任一項不成立即停止並回報；通過後 commit，回到第 2 步處理下一個行為。
- 同一步嘗試兩次仍失敗：停下來，說明卡在哪裡，請使用者決定方向。

## 完成回報
```
改了什麼：…
為什麼：…
影響哪些地方：…
如何驗證：測試／型別檢查／lint 的實際輸出摘要
未完成或不確定：…（沒有就寫「無」）
範圍外發現：…（看到但沒動的問題）
```
